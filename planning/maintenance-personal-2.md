# VoiceInk personal.2 维护交接

2026-11-13，用户批准修复远程 Ollama 设置和自动学习服务选择，重新云构建、发布 DMG，并将有用工作收敛到 main、删除无用过程分支。原有个人功能、模式、提示词、数据库和签名身份继续保留。

## 本次修复范围

- 本地服务设置页单独保存最后浏览的服务器，不再每次重置成全局默认。浏览服务器不等于修改默认服务器。
- 模型输入即时保存；列表没有返回手填/已保存模型时仍可显示，不依赖按 Enter 才保存。
- 多个 OllamaService 实例写配置前合并最新持久化数据，异步返回不能覆盖新偏好、复活已删除服务或把旧 URL 结果应用到新 URL。URL 变更清除连接状态及内存获取结果，保留用户手填模型。
- Auto Learn 使用主应用共享的 AIService，列出已配置 provider；选择 Ollama 后独立选择服务器和模型。审核请求使用保存的精确 endpoint，不回退到另一个服务器；历史默认选择兼容读取当前默认服务。
- 审核通过记录绑定 provider、model、server ID 和 endpoint，避免换服务后复用另一服务的批准；待审数据不因此删除。
- 不改变既有 Mode 的服务器和模型，不修改中文 V3 prompt，不恢复已取消的一次性 Ollama 服务故障排查。

## 回归与构建

CI 执行八组测试（原七组加 AutoLearnConfigurationTests），包括跨实例保存、延迟刷新、删除/改 URL、模型显示、Auto Learn 精确端点和无变化快照。实际执行数量与通过结果见每个源码提交的 Actions 和 DMG 元数据，不用测试文件数量代替通过结果。

正常 main/upgrade 构建现在依次编译测试、原证书签名、生成并挂载校验 DMG；测试摘要经哈希验证进入 DMG 元数据。发布是独立显式操作，只接受完全相同源码 SHA 的成功完整构建，不覆盖旧 Release。详细操作见 scripts/ci/README.md。

main 合并保留过程分支提交历史，只把可继续使用的正式构建/打包/发布流程放在当前树中。旧基线、导入和签名探针不会继续触发；已审计过程分支只有在 head 未变化且位于 main 历史中才删除。

## Auto Learn 另一个已调查但未在本次修改的问题

用户报告“没手动修正也出现建议，手动修正反而没有”。源码证明正常转录交付使用最终贴入输入框的润色成品作为基线，不直接比较 ASR 原文与润色成品。目前缺乏该用户具体文本和操作序列，不能把某个潜在路径当作他的已确认原因。

已确认的原版限制：
- 粘贴后约 120ms 建立 AX 快照；仅在离开输入框、下一次录音/粘贴或最多 60秒观察结束时结算，不是每键实时学习。
- 改完直接发送，输入框在最终快照前清空，会丢失修正；自动发送主动取消观察；VoiceInk 自己窗口不捕获。
- 无空白中文只按部分 ASCII 标点切分，中文标点不构成分隔；整段改一字可能被作为整段替换，超过32字的无空格候选在AI审核前就被过滤。
- 第二次程序粘贴完成后才结算前一次观察；连续使用“粘贴上次原文/润色结果”替换同一输入框可能把程序自己的修改当作修正。正常新录音会提前结束上一观察，不能据此断言所有新录音都存在同样误判。

本次未重写捕获或中文分词，也未扩大观察范围。后续需具体复现后单独处理，不应声称本次模型设置修复解决上述全部问题。Mac 实际辅助功能捕获、录音、远端请求仍需用户环境验证；不将云端单元测试当作实机使用验收。
